# V1.1 — usability and hardening

V1.1 reduces the taps and scrolling between a question and card text. It retains
V1's TypeScript/Vite architecture, card schema, MTGJSON transformation, name-search
ranking, symbol font, service worker and GitHub Pages workflow.

## Time to information

- The detail eyebrow is removed, navigation/title/panel/ruling gaps are smaller,
  and panel padding is reduced. Oracle paragraphs still have visible separation
  and use the existing serif type. At 375 × 812, Necropotence's first ruling is
  visible without scrolling; Sol Ring's entire reference fits comfortably.
- New search takes one tap from details to an empty, focused search field. Focus
  happens synchronously in the tap handler, allowing a mobile keyboard where the
  browser permits it. It pushes a search history entry, so browser Back can return
  to the card. Back to search retains the earlier query, selected result and saved
  result scroll position. Deep links without an app-created history entry return
  locally to search rather than taking the user out of the app.
- Five unique recent cards appear on an empty search screen, newest first. A
  revisit moves a card to the front. History persists in localStorage, malformed
  data is ignored, unavailable card names are removed, and blocked storage falls
  back to the current session. Clear recent restores the example-search state.
- Previously implemented typo suggestions remain a no-results fallback; ordinary
  matching/ranking is unchanged. No new search dependency or dataset is added.

## Tests and data findings

30 tests pass (26 Node + 4 Python). The fixed, field-reduced MTGJSON excerpt under
`tests/fixtures/` covers Sol Ring, Necropotence, Sheoldred, Bala Ged Recovery,
Fire // Ice, Bonecrusher Giant // Stomp, Jace, The Eldest Reborn, and Greater
Morphling's 600+ characters of rules text. Tests pass the fixtures through the
actual Python transformer and actual detail renderer. They verify faces, ability
paragraphs, mana, P/T, loyalty, Saga chapters, dated rulings and absence of
truncation. Existing synthetic tests cover duplicated printings and rulings,
out-of-order faces/rulings and missing optional values.

No card-data transformation defects were found. The transformer and production
card-data artifact were not changed. Rendering was extracted into a small pure
function solely to make the existing output directly testable.

## Offline evidence and limits

The existing worker precaches every production file: HTML, hashed JS/CSS, dataset,
manifest, icons, Mana stylesheet/font and license notices. Navigation resolves to
the cached index within the site's scope. A hash of production files identifies
a version; installation must cache all files before that worker can activate.
Failed installs remove only their new cache. Activation cleans older caches for
this app's scope; the fully installed update waits for the user's reload action.

Automated tests simulate a worker restart with only persistent cache storage
remaining, make network access fail, and retrieve the shell, dataset/rulings and
font. Other tests verify interrupted-install rollback and cache isolation. These
are deterministic worker-logic tests, not an installed Android browser emulator.

Manually verified in the production build on local Safari:

1. Load online and wait for Available offline; view Necropotence.
2. Close all tabs for that production test origin.
3. Stop the preview server, making the app origin unavailable.
4. Open the root URL in a fresh tab (not a reload or back-forward restore).
5. Confirm Recently viewed survived; open Necropotence and read all four dated
   rulings, Oracle paragraphs and locally cached mana symbols.
6. Tap New search, type bolt and open Lightning Bolt with the server still stopped.

Also checked 375px mobile layout, desktop layout, query-preserving Back, search
focus and history clearing. This does not establish Android home-screen cold
launch, browser-process termination, storage eviction behavior or deployment
headers. Those require the device check below. The existing Available offline
indicator waits for an active worker; it is not a guarantee against later browser
storage eviction. The entire installed-PWA scenario was not claimed as automated.

## Size and performance

Same 35,282-card snapshot; dataset byte-for-byte unchanged at 29,228,731 bytes
(6,732,474-byte gzip estimate). No new first-load network requests are introduced.
The same complete dataset is loaded and indexed before search; five stored names
are then reconciled with that dataset. Cold online/offline load behavior is otherwise
unchanged, including the initial complete-cache download.

| Desktop Node 24 measurement | Baseline | V1.1 |
|---|---:|---:|
| JS, raw | 10.86 kB | about 11.54 kB |
| JS, gzip | 4.70 kB | about 4.88 kB |
| CSS, raw | 6.92 kB | 7.85 kB |
| CSS, gzip | 2.17 kB | 2.35 kB |
| JSON read + parse | 123 ms | 124 ms |
| Name indexing | 87 ms | 82 ms |
| Search median | 3.43 ms | 3.38 ms |
| Search p95 | 8.13 ms | 7.97 ms |

These are a local 300-query sample, not phone benchmarks. Timing differences are
normal measurement noise; there is no demonstrated search regression. `sol`
returns Sol Ring first, `bolt` places Lightning Bolt fourth, and `sheold` returns
Sheoldred, the Apocalypse first. Exact/prefix ranking and result mana/type content
remain unchanged. `npm run bench` reproduces the measurement.

## Android installed-PWA checklist

1. Deploy V1.1, open the HTTPS Pages site online in Chrome, accept Update ready
   if shown, and wait for Available offline. Install/Add to Home screen.
2. Open six distinct cards (include Necropotence and a double-faced card). On an
   empty search, verify only the five newest appear. Reopen one and check it moves
   to first without a duplicate.
3. Close Chrome tabs for this site and dismiss both Chrome and the installed app
   from Recents. Enable airplane mode and ensure Wi-Fi is off.
4. Launch from the home-screen icon. Verify history appears. Open Necropotence's
   text and dated rulings; search sol, bolt and sheold. Open a multi-face card.
5. From details, tap New search: the empty field should focus and show the keyboard.
   Open another card, then Back to search: the prior query/results should return.
   Use Android/browser Back to confirm the navigation sequence remains sensible.
6. Clear recent, close/reopen offline, and confirm the example searches return.
7. Reconnect, deploy a later update, and verify the old copy stays usable until the
   new update is fully saved. During an update download, disconnect and relaunch:
   the previous complete version should still work. Reconnect to finish updating.

## V1.2 architectural recommendation — no implementation

Keep the current card name index specialized. Add a separate rules-document
index for Comprehensive Rules sections, glossary entries and mechanics, with
stable rule identifiers, document kinds, source/version dates and explicit links.
A small query coordinator can merge their results into clearly labelled Cards and
Rules groups. This preserves predictable exact card-name lookup while enabling
full-text term matching and weighting appropriate to prose.

One undifferentiated name/prose index would let common words in long rules crowd
out card hits. In a merged experience, exact card names and explicit rule numbers
should win, then card/keyword prefixes, glossary titles, and prose relevance.
Contextual links should use validated rule identifiers rather than inferred
interaction answers. Existing card records, MTGJSON pipeline, card renderer,
normalization, history storage, UI colors/symbols, Pages deployment and atomic
cache strategy can stay unchanged. Rules need their own renderer and indexing
strategy; no V1.1 refactor anticipates them.

Text-only rules are likely smaller than the current card/ruling corpus, but the
size of a token/postings index and duplicated cross-reference metadata can be
material. Measure raw/gzip bytes, parsed memory, indexing time and phone latency
from a real rules snapshot before choosing an index format or extra dependency.
The offline snapshot must include matching versions of rule text, index and links.

Before V1.2, agree on source/licensing, update cadence, version identifiers and
link stability; define a document schema and query-intent/ranking policy; build a
small evaluation set of actual at-table questions and ambiguous card/mechanic
names; and set phone TTI, download and memory budgets. Compare specialized indexes
against a unified one on that set before choosing. No rules, glossary, Omnisearch,
AI interpretation or other V1.2 functionality is included in this release.
